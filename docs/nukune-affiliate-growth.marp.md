## 1) いまの強みと前提

- **強み**: 「相性で選べる」「60分以内の空き枠」「提携予約」「7日トライアル（自動継続）」
- **信頼表示**: インターネット異性紹介事業 届出番号の明示、特商法ページの整備済み
- **前提**: 成人向け領域は主要汎用広告の配信制限が厳しい → 専用ネットワーク＋自社アフィでの獲得が現実的
- **全ページ**で、適切な年齢ラベルやRTAタグ、外部送信ポリシーへの導線を明確化

## 2) チャネル戦略（優先順位）

- **A. SEO（中長期の主軸）**: 「都市/駅 × 今すぐ × 条件」テンプレで量産。FAQと構造化データで強化
- **B. 有料配信（立ち上げ）**: アダルト特化ネットワーク（ExoClick / TrafficJunky / JuicyAds）で小額テスト→スケール
- **C. オーガニックSNS（補完）**: Xは広告不可のため教育系・非露骨運用（年齢・注意表示遵守）
- **D. 自社アフィ（増幅）**: 招待制で厳選募集。S2S計測で返金/解約控除も反映

参考: [ExoClick](https://www.exoclick.com) / [TrafficJunky](https://www.trafficjunky.com) / [JuicyAds](https://juicyads.com)

## 3) 国内ASPの活用（最短で規模化）

- **A8.net**: 国内最大級。媒体網と運用ノウハウ厚く、初期〜中級の横展開が速い  
- **バリューコマース**: 成果地点・トラッキング設計の柔軟性が高い  
- **ACCESSTRADE**: 日本/東南アジア。CPA/CPL系が強い。海外流入も視野なら候補  
- **afb**: 承認フローや媒体審査運用がわかりやすい。特化ジャンルと相性良  
- **Link-A**: アフィリエイター連携が手厚い

導入フロー（広告主）:
1. 広告主登録 → 成果条件（例: 有料申込/初回課金/継続N回）・承認基準・計測期間を定義  
2. 計測タグ or S2Sポストバック（サンクスページ or サーバ間推奨）  
3. クリエイティブ提示とNGルール明確化（ブランド名入札/Cookieスタッフィング等）  
4. 媒体募集・不正監視・承認/否認運用・月次精算

## 4) 自社アフィ / リファラル（SaaS活用）

- **Rewardful**: Stripe直結。紹介リンク/クーポン、定期課金の自動按分  
- **FirstPromoter**: Stripe/Chargebee/Paddle等と双方向。返金/アップグレード追従  
- **Tapfiliate**: S2Sポストバック対応。クーポン紐づけ/リカーリング/返金連動  
- **impact.com**: 大規模パートナープラットフォーム（複雑な契約・支払）

自社フロー: 登録（URL提出）→ 承認 → リンク発行 → クリック記録（1st-party） → 課金Webhook → S2S記録 → 還元

---

## 5) 報酬設計とキャッシュバック上限（景表法）

- 紹介者: CPS/レベニューシェア（例: 初回20%/継続10%） or CPA（有料登録1件¥X）
- **購入者への直接還元**（キャッシュバック/ポイント）を誰でも受けられる特典とする場合は「総付景品」の上限を順守:
  - 取引額1,000円未満 → 最大200円  
  - 取引額1,000円以上 → 取引額の20%まで
- 例: 月額¥2,000の初回CBは最大¥400目安（総付景品に該当する設計なら）
- それ以上を狙うなら「抽選型（一般懸賞）」等へ設計変更（要専門家レビュー）

参考: [消費者庁](https://www.caa.go.jp)

---

## 6) 2023/2024 法務・表示チェック

- **ステマ規制（景表法）**: 「広告/PR」表示を明確化。媒体・インフルエンサーにも開示ルール徹底
- **Cookie/外部送信規律（改正電気通信事業法）**: 送信先・目的を外部送信ポリシーで通知/公表、CMPや同意方針を検討
- **個人情報保護法（APPI）**: 取得項目・利用目的・第三者提供・海外移転をプライバシーポリシーに明記
- **インボイス制度**: 個人アフィリエイター直払い時は適格請求書の取扱い留意（ASP経由はASP側処理）
- **資金決済法（前払式支払手段）**: 自社ポイント残高の取り扱いに注意（届出/発行保証金等の要件）

参考: [JIAA](https://www.jiaa.org) / [日本資金決済業協会](https://www.s-kessai.jp) / [金融庁](https://www.fsa.go.jp)

## 7) 実装メモ（S2S寄り：最小構成）

イベント流れ: クリック → 課金 → ポストバック

- クリック時: `/r?aff=AFF123&subid=UUID` を受け取り、自社DBに `clickId, affiliateId, userAgent, ip, timestamp` を保存。1st-party Cookieも設定
- 決済時: Stripe Webhook（例: `checkout.session.completed`）で、顧客の `clickId` を会員/セッションから取得
- S2Sポストバック（例）:  
  `GET https://tracker.example.com/postback?click_id=...&order_id=...&amount=...&status=approved`  
  - 重複防止/リトライ/署名付き
- 返金/チャーン: `charge.refunded` 等で減額/取消を反映（リカーリングは月次自動）

## 8) 不正対策（初期ルール）

- 自己アフィ禁止（同一会員ID・決済手段の自己購入を否認）。規約に明記
- 同IP/端末指紋/短時間多重/ブランド名入札/Cookieスタッフィングの禁止
- クーポン紐づけ（特定アフィリエイター専用コード）でラストクリック偏重を緩和
- ログ基盤: IP / UA / 端末指紋 / アカウントID / 決済トークン一部ハッシュ化を横断監視

---

## 9) LP/オンサイト最適化（即効）

- **ゲート緩和**: 候補を一部プレ表示 → 価値体験後に登録を促す
- **CTA一本化**: 「60分以内に会える候補を見る（無料）」を第一CTAに（A/Bで「今すぐ登録」と比較）
- **安心表示**: ヒーロー直下に「届出番号・年齢確認・匿名利用」をアイコン+1行で固定表示
- **トライアル透明性**: 「7日無料→自動継続¥1,980/月・いつでも解約」を価格表直上に常時表記

## 10) 計測とKPI（初期セット）

- 主要イベント:  
  `view_candidates → start_signup → complete_signup → outbound_to_partner → confirmed_booking(S2S)`
- 発行: 媒体別UTM + `clickId`  
- 確定: S2Sで成果確定（返金/キャンセルは減額）
- ダッシュボード: チャネル別有料登録率 / 7日継続率 / 月次継続率 → LTV/CAC判断

## Appendix D: 実装補足（S2S設計の要点）

- **署名**: 共有鍵で `HMAC-SHA256`（`clickId|orderId|amount|ts`）を付与し改ざん防止
- **重複排除**: `orderId + status` の冪等制御（DBでユニーク制約 or ロック）
- **リトライ**: 一時障害時は指数バックオフ。最長TTLと上限回数を設定
- **個人情報**: ポストバックにはPIIを含めない（識別子はハッシュ化または擬似ID）
- **監査ログ**: 受信/送信の全PayloadとHTTPステータスを保存（法務・運用のため）
